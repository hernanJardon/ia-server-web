Instancias

Descargar un modelo

Del registro de Ollama (qwen2.5:14b, llama3.2:3b-instruct-fp16) o un GGUF de Hugging Face (hf.co/usuario/repo:Q4_K_M). Si cancelas, lo ya descargado se conserva y la siguiente vez continúa.

Para cuantizar a tu gusto, descarga la variante -fp16 del modelo: Ollama solo cuantiza desde F16 o F32.

Subir un GGUF

El archivo viaja al panel, se registra en Ollama y se crea el modelo. La plantilla de chat se toma de los metadatos del GGUF.

Cuantizar

Crea una copia del modelo con otro número de bits por peso usando llama-quantize de llama.cpp. La copia conserva la plantilla, el prompt de sistema y los parámetros del original. Lo ideal es partir de un modelo F16 o BF16.

Se ejecuta en la CPU del servidor y tarda de uno a varios minutos según el tamaño. Necesita espacio libre en disco para el resultado.

Cuantizaciones

Crear variante

Un modelo nuevo que reutiliza los pesos de otro (no ocupa disco extra) con su propio prompt de sistema y parámetros. Equivale a un Modelfile con FROM, SYSTEM y PARAMETER.

Plantilla de prompt (avanzado)

Chat de prueba

Para comprobar un modelo recién creado o entrenado. La conversación no se guarda y el modelo se descarga de memoria 5 minutos después del último mensaje.

Escribe un mensaje para empezar. Ctrl+Enter lo envía.

Entrenamiento LoRA

Ollama no entrena. El panel lanza un fine-tuning LoRA con PyTorch sobre el modelo original de Hugging Face y registra el adaptador en Ollama encima del modelo equivalente que ya tienes (por ejemplo Qwen/Qwen2.5-7B-Instruct sobre qwen2.5:7b).

Nuevo entrenamiento

El modelo base se reparte entre las cuatro GPU. Descarga de memoria los modelos de Ollama antes de entrenar: compiten por la misma VRAM. Con 4 x 12 GB y QLoRA, modelos de hasta unos 14B entrenan con holgura.
